# PROD-006 — правила зачёта дисциплин и образовательной программы

## Идентификация
- **ID:** `PROD-006`
- **Название:** Определить академические правила зачёта дисциплин и завершения программы
- **Статус:** [~] In progress
- **Владелец:** MAGNUS project workflow
- **Создано / обновлено:** 2026-11-11

## 1. Цель и ожидаемый результат
Определить однозначные правила, по которым MAGNUS фиксирует зачёт отдельной дисциплины, учебного блока и программы в целом. Разделить факт прохождения учебных элементов, оценку практики, завершение занятия и итоговую аттестацию. Результат — нормативная продуктовая модель для будущей серверной реализации, академического паспорта и ведомости.

## 2. Контекст и текущее состояние
- PROD-001…PROD-005 завершены; обучение самостоятельное и асинхронное.
- Каноническая структура находится в `tgcloud/lib/academicCatalog.js`: программа → учебные блоки (terms) → дисциплины (subjects) → lessonIds; у дисциплины есть признак `required`.
- Три демонстрационные программы содержат по два учебных блока, по одной обязательной дисциплине в каждом и по три занятия в дисциплине; всего шесть занятий на программу.
- `savePracticeReview` сохраняет последнюю оценку практики по рубрике 0–6; зачёт практики сейчас определяется результатом `pass` (не менее 4/6 и без нулей).
- `completeLesson` требует зачисление, правильный контрольный ответ, последовательное открытие и зачтённую практику для занятия.
- Итоговый экзамен сейчас доступен после завершения всех шести занятий; один из действующих обработчиков использует порог 70% и максимум три попытки. В `studentData.js` обнаружены два одинаковых action-ветвления итогового экзамена; первое перехватывает запросы и делает вторую реализацию недостижимой. Это техническое наблюдение, не исправляется в PROD-006.
- Академический паспорт показывает количество завершённых занятий, зачтённые практики и результат экзамена; поле `completed` вычисляется как все занятия завершены и экзамен сдан.
- PROD-007 отдельно определяет проходные пороги, количество попыток, пересдачи и апелляции. PROD-006 не должен переопределять эти параметры.
- Сертификат MAGNUS — внутренний документ, не государственный диплом и не аккредитованная квалификация.

## 3. Границы

### IN — входит
- Определить смысл зачёта дисциплины и его обязательные условия.
- Определить правила завершения учебного блока и программы.
- Разделить завершение занятия, зачёт практики, зачёт дисциплины и итоговую аттестацию.
- Установить правила обязательных и необязательных дисциплин/занятий.
- Определить правила учёта повторных попыток и сохранения достигнутого зачёта на уровне принципов, не задавая лимиты.
- Определить поведение при изменении версии каталога и состава программы на уровне академического принципа.
- Зафиксировать связь академического результата с активностью, статусами программы и будущей моделью оценивания.
- Добавить модель в документационный checker и негативный тест отсутствующего документа.

### OUT — не входит
- Выбор числовых проходных порогов, лимитов попыток, периодов пересдачи и правил апелляции — PROD-007.
- Правила заморозки, возврата и прекращения подписочного доступа — PROD-008.
- Правила и юридические формулировки внутреннего сертификата — PROD-009.
- Изменение runtime, API, БД, схемы каталога, существующих student records или UI.
- Исправление обнаруженного дублирующего обработчика экзамена; это отдельный implementation WP.
- Создание новых программ, занятий или учебного контента.

## 7. План тестирования

### Автоматические
- `npm run check:docs` — обязательный документ, структура и ключевые правила.
- `npm run test:docs` — позитивный сценарий и негативный тест отсутствующего документа.
- Полный workflow `MAGNUS visual smoke tests`: tutor coverage, payment invariants, backend syntax, production build, desktop/mobile Playwright smoke.

### Ручные
- Сверить все правила с `academicCatalog.js`, `studentData.js`, `ACADEMIC_STATUS_MODEL.md` и `LEARNING_ACTIVITY_MODEL.md`.
- Проверить логические сценарии: неполная дисциплина, все обязательные занятия пройдены, optional-дисциплина не пройдена, несколько дисциплин в блоке, все блоки завершены без экзамена, экзамен сдан.
- Проверить, что текст не подменяет внутренний зачёт государственной квалификацией.
- Telegram-проверка не требуется: runtime не меняется.

### Негативные и граничные сценарии
- Одна незачтённая обязательная практика не позволяет завершить соответствующее занятие/дисциплину.
- Неполное обязательное занятие не засчитывается даже при высоком среднем балле по другим элементам.
- Необязательная дисциплина не блокирует зачёт блока/программы, если правила программы явно не делают её обязательной.
- Завершение всех занятий без успешной итоговой аттестации не означает завершение программы.
- Повторная попытка сама по себе не аннулирует ранее достигнутый зачёт; случаи отзыва/аннулирования результата требуют отдельного формального решения и аудита.
- Изменение будущей версии каталога не должно незаметно менять исторический результат студента.
