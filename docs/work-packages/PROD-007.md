## 7. План тестирования

### Автоматические
- `npm run check:docs` — обязательный документ и согласованность активного WP.
- `npm run test:docs` — позитивные/негативные тесты, включая отсутствие политики оценивания.
- Полный workflow `MAGNUS visual smoke tests`: tutor coverage, payment invariants, backend syntax, production build, desktop/mobile Playwright smoke.

### Ручные
- Source review `studentData.js`, `academicCatalog.js`, `ASSESSMENT_AND_COMPLETION_POLICY.md`.
- Проверить пороговые примеры практики: 2+1+1 — pass; 2+2+0 — revise; 1+1+1 — revise.
- Проверить экзаменационную формулу без округления: 69,6% — fail; 70% — pass.
- Сверить три стандартные попытки и правила дополнительной пересдачи с текущим backend.
- Убедиться, что процесс апелляции не описан как уже работающий.

### Негативные и граничные сценарии
- Повторная доставка одного запроса не расходует дополнительную попытку.
- Незавершённая экзаменационная сессия не расходует попытку.
- После pass практика/экзамен не может быть молча понижен повторной попыткой.
- Нулевой балл по одному критерию блокирует pass практики даже при сумме 4+.
- Округление отображаемого процента не влияет на проходной результат.
- Апелляция не удаляет исходную попытку и не ухудшает результат из-за самого факта обращения.
- Ошибочная попытка сохраняется как voided с причиной и возвращённым лимитом.
