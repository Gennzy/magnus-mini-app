# PROD-005 — активность и участие в самостоятельном обучении

## Идентификация
- **ID:** `PROD-005`
- **Название:** Определить правила активности и участия в асинхронном обучении MAGNUS
- **Статус:** [x] Done
- **Владелец:** MAGNUS project workflow
- **Создано / обновлено:** 2026-11-11

## 1. Цель и ожидаемый результат
Определить, какие серверно подтверждённые действия считаются учебной активностью, что переводит зачисление `enrolled` в `active`, какие события не должны учитываться, как показывать последнее участие и как не путать академический статус с регулярностью посещений.

Результат — однозначная модель активности для самостоятельного асинхронного университета, пригодная для будущей реализации и аналитики.

- `submitAssignment` сохраняет отправки, но в текущем коде не проверяет зачисление на связанную программу; пока это событие не квалифицируется.

## 7. План тестирования

### Автоматические
- `npm run check:docs` — обязательный документ и согласованность активного WP.
- `npm run test:docs` — позитивные и негативные тесты, включая отсутствие документа активности.
- Полный workflow `MAGNUS visual smoke tests`: tutor coverage, payment invariants, backend syntax, production build, desktop/mobile Playwright smoke.

### Ручные
- Source review `studentData.js`, `tutor.js`, `schema.js`, `main.js`, `ACADEMIC_STATUS_MODEL.md`, `STUDENT_LIFECYCLE.md`.
- Проверить, что `updated_at` меняется от технических операций и потому не используется как дата последней учёбы.
- Проверить матрицу qualifying/non-qualifying на одном студенте с двумя программами.
- Telegram-проверка не требуется, потому что runtime не меняется.

### Негативные и граничные сценарии
- Обычный вход и чат с AI не переводят `enrolled` в `active`.
- Черновик и заметка не считаются участием.
- Принятая практика с `revise` считается участием, но не зачётом.
- Отправка assignment без проверки зачисления не считается qualifying event.
- Повтор транспортного запроса не создаёт дубликат события.
- Отсутствие событий 7/30/90 дней не меняет академический статус.
- Отпуск по одной программе не блокирует события по другой активной программе.

- **Риск:** подмена качества обучения количеством событий. Снижение — метрики участия и метрики результата хранятся отдельно.

- **Обратная совместимость:** payload и история студентов не меняются.
