# ADR-0004: Сервер — источник истины для академических результатов

- **Статус:** Accepted
- **Дата фиксации:** 2026-11-11
- **Связанный WP:** GOV-006
- **Заменяет / заменён:** Нет

## Контекст
Зачисление, завершение занятий, оценки практики, экзамены, сертификаты и академические статусы влияют на учебный прогресс и документы. Клиентское состояние может быть изменено пользователем и не может считаться доверенным.

## Решение
Критические академические действия и результаты проверяются и сохраняются на backend. Endpoint использует подтверждённый Telegram initData-контекст для определения текущего пользователя. Клиент не должен самостоятельно назначать себе зачисление, оценку, завершение курса или сертификат.

## Рассмотренные альтернативы
- Принимать готовый прогресс и оценки от клиента — отклонено из-за возможности подмены данных.
- Использовать локальное состояние только для отображения черновиков — допустимо для некритичных данных, но не как источник официального академического результата MAGNUS.

## Последствия
### Положительные
- Академические правила централизованы на сервере.
- Уменьшается возможность подделки прогресса и доступа к чужой карточке через клиентский ID.

### Отрицательные / компромиссы
- UI зависит от доступности backend.
- Серверные проверки и схема данных требуют регрессионных тестов.

### Ограничения и риски
- Требуется отдельно проверять авторизацию каждого endpoint и защиту от повторных событий.
- Серверная модель сама по себе не является полной security-аудит-проверкой.

## Подтверждение
- `tgcloud/endpoints/studentData.js`: `enrollProgram`, `completeLesson`, `getAcademicPassport`.
- `tgcloud/endpoints/tutor.js`: серверная проверка практики и сохранение результата.
- CI payment invariants и backend syntax checks не заменяют полный security audit.
