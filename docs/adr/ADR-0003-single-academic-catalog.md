# ADR-0003: Единый серверный каталог учебных программ

- **Статус:** Accepted
- **Дата фиксации:** 2026-11-11
- **Связанный WP:** GOV-006
- **Заменяет / заменён:** Нет

## Контекст
Факультеты, программы, учебные блоки, дисциплины и lesson ID используются в нескольких серверных сценариях: публикация каталога, зачисление, проверка завершения занятий и академическая сводка.

## Решение
Использовать `tgcloud/lib/academicCatalog.js` как единый источник истины для структуры каталога и связей программ с занятиями. Новые серверные сценарии должны получать структуру из этого каталога, а не создавать независимые дублирующие списки ID.

## Рассмотренные альтернативы
- Дублировать список уроков в каждом endpoint — проще локально, но создаёт риск расхождения правил и контента.
- Хранить независимый каталог на клиенте — клиентская копия может быть устаревшей и не должна определять серверные академические правила.

## Последствия
### Положительные
- Согласованные связи факультет → программа → блок → дисциплина → занятия.
- Серверные проверки могут опираться на общий каталог.

### Отрицательные / компромиссы
- Изменение каталога требует проверки всех потребителей и совместимости с существующими зачислениями.
- Каталог пока содержит три демонстрационные программы, а не полный университетский перечень.

### Ограничения и риски
- Не менять существующие ID программ и уроков без отдельной миграционной стратегии.
- Наличие каталога не означает, что учебный контент полностью разработан или аккредитован.

## Подтверждение
- `tgcloud/lib/academicCatalog.js`: `ACADEMIC_CATALOG`, `getProgramLessonIds`, `getPublicAcademicCatalog`.
- `tgcloud/endpoints/studentData.js`: импорт каталога для серверной проверки и паспорта.
