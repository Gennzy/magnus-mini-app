# Архитектурные решения MAGNUS (ADR)

Этот каталог фиксирует важные архитектурные решения и их причины. ADR описывает принятое решение, а не просто текущее устройство кода.

## Статусы
- **Proposed** — обсуждается, ещё не принято.
- **Accepted** — принято и действует.
- **Superseded** — заменено более новым ADR (с обязательной ссылкой).
- **Deprecated** — больше не рекомендуется, но исторически важно.

## Правила
1. Один ADR — одно решение и его контекст.
2. Записывать причины, альтернативы и последствия, включая компромиссы.
3. Не переписывать историю задним числом: изменение решения оформлять новым ADR со ссылкой на предыдущий.
4. Не превращать предположение в факт. Если дата/автор/обоснование неизвестны, прямо указать это.
5. ADR не заменяет MASTER_ROADMAP, PROJECT_STATE, WP или документацию API.
6. При изменении архитектуры в рамках WP проверить, нужен ли новый ADR.
