# ADR-0005: AI-провайдер вызывается только с backend

- **Статус:** Accepted
- **Дата фиксации:** 2026-11-11
- **Связанный WP:** GOV-006
- **Заменяет / заменён:** Нет

## Контекст
AI-наставник использует внешний API Groq. API-ключ является секретом и не должен быть доступен в исходниках или браузерном bundle.

## Решение
Вызовы Groq выполнять только из серверного endpoint. Ключ и настройки модели хранить на серверной стороне; клиент взаимодействует с tutor endpoint, а не с Groq напрямую.

## Рассмотренные альтернативы
- Вызывать Groq из браузера с ключом — отклонено, так как ключ станет доступен пользователю.
- Встраивать ключ в сборку — отклонено по той же причине.

## Последствия
### Положительные
- Секретный ключ не требуется передавать клиенту.
- Сервер может применять лимиты и ограничения модели.

### Отрицательные / компромиссы
- Запросы к наставнику зависят от доступности backend и внешнего API.
- Серверная обработка добавляет задержку и эксплуатационные расходы.

### Ограничения и риски
- Требуются контроль расхода, лимиты, fallback и тестирование качества ответов.
- Нельзя обещать безошибочность AI или выдавать его за человека.

## Подтверждение
- `tgcloud/endpoints/tutor.js`: вызов `https://api.groq.com/openai/v1/chat/completions`.
- Серверные AI settings и лимиты запросов.
- Необходимо сохранять ключи вне клиентской части и CI-логов.
